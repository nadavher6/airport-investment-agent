Top issues

  • G7 rank-fastest — the only failure. On a broad "rank the fastest-growing large hubs" query the agent called find_airports_by_region six times (one per region) to enumerate candidates, hit the 6-step tool cap, and ended the turn with an empty answer. Root cause: (a) MAX_TOOL_STEPS is too low for enumerate-then-rank queries, and (b) the loop returns empty instead of forcing a final answer when steps run out.
  • Fix: raise the step budget, and on the last step require a prose answer (never emit empty). Better, steer the model to score a candidate set in one score_airports call, or add a "list all large hubs" tool so broad rankings don't burn steps on region lookups.
  • Watch: relative scoring magnifies tiny gaps (e.g. 81.9% vs 81.7% load factor → 100 vs 0). The agent caught and explained this every time — good — but it's a UX sharp edge worth smoothing in the score itself.
